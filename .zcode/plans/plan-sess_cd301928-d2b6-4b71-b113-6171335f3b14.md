# Ghar v2.0.0 — chores-first rebuild of the motor app

**Product**: one household app, no visible login, where everything due is a chore. Motor = two chained chores (turn on → spawned close chore). Bills = chores with an amount and strict deadlines. The home-invoice purchase ledger is the one separate section. Strict deadlines ring the full-screen insistent alarm **on the assignee's phone only** (rotating chores → today's assignee). Soft deadlines just sit on the today list. App name: **Ghar** (repo stays `motor`; Android applicationId unchanged so the APK updates over installed v1.0.1).

Working decisions to veto at review time: assignee-only alarms, the name "Ghar", destructive schema wipe (v1 data is unused).

---

## Phase 1 — Backend: migration `0003_chores.sql` (destructive)

Drop `runs`, `assignments`, `swap_requests`; drop `households.code`, `reminder_time`, `run_minutes` (keep `snooze_minutes`, `created_at`). Keep `members`, `device_accounts`, `is_member()`, pool RPCs.

**New tables** (all carry `household_id` so the existing realtime channel pattern keeps working):

```sql
chores (
  id, household_id fk, title text 1..80, note text,
  assignee_member_id fk null,            -- fixed person; null when rotate
  rotate bool default false, rotation_offset int default 0,  -- per-chore rotation seed
  strict bool default false,             -- strict → native alarm on assignee's phone
  due_at timestamptz null,               -- one-off deadline
  repeat_days int null (1..365),         -- recurring: every N days (1=daily, 7=weekly)
  repeat_monthly_day int null (1..28),   -- recurring: day of month (bills)
  time_of_day time default '10:00',      -- recurring: deadline time that day
  duration_minutes int null (1..120),    -- set → "start" spawns a close chore (motor)
  amount numeric(12,2) null,             -- bill amount
  spawned_from uuid null → chore_events, -- close-chore → its start event
  active bool default true, created_by, created_at,
  check: exactly one of due_at / repeat_days / repeat_monthly_day set,
  check: rotate ⇒ assignee is null
)

chore_events (        -- the single completion record; generalizes runs
  id, household_id fk, chore_id fk, on_date date,
  status ('started','done','skipped'), started_at/by, done_at/by,
  unique (chore_id, on_date)
)

chore_assignments (   -- per-occurrence override; generalizes assignments + swap payback
  chore_id, on_date, member_id, pk (chore_id, on_date)
)

swap_requests (       -- evolved: + chore_id; status ('pending','accepted','canceled')
  id, household_id, chore_id, on_date, from_member_id, to_member_id null, status, created_at, resolved_at/by
)

purchases (           -- the ledger (home-invoice port)
  id, household_id, member_id (who bought), item text 1..120, amount numeric > 0, created_at
)
```

**Rotation math, single source**: `assignee = active_members_by_rotation_order[(dayNumber(date) + chore.rotation_offset) % n]` — SQL `rotation_assignment(p_chore, p_date)` and TS must match (rotation_offset is stored, so no hash lockstep). `rotation_offset` = `max(offset)+1` among the household's rotating chores, assigned by `create_chore`.

**RPCs** (all security-definer, `set search_path = public`):
- `ensure_household(p_name)` → `(household_id, member_id, created)` — the whole no-login flow: if the device's auth_uid has an inactive member, reactivate + rename; if it has an active member, return it; if no household exists, create one **and seed the default chores** ("Turn on the motor": rotate, strict, daily 10:00, duration 10 — close chore is spawned, never seeded); else add a new member with `rotation_order = max+1`.
- `create_chore(...)` — validates and sets `rotation_offset`; edits via direct REST update.
- `start_chore(p_chore, p_on_date)` — atomic: upsert event `started`; if the chore has `duration_minutes`, delete any stale spawned close-chore and insert one-off chore ("Close the motor", `due_at = now() + duration`, strict, assignee = starter, `spawned_from` = event).
- `complete_chore(p_chore, p_on_date)` — upsert event `done`; if the chore is spawned, also stamp its parent event done.
- `skip_chore(p_chore, p_on_date)` — event `skipped` (not shown as missed).
- `accept_swap(p_request_id)` — generalized: cover = override for that chore/date → accepter; payback = scan that chore's next occurrence assigned to the accepter → override → requester. Same semantics as today, parameterized by chore.
- `cancel_swap`, `claim_device_account`, `release_device_pool` unchanged. Drop `create_household`, `join_household`, old rotation helpers. Add `ping()` (anon keep-alive target).
- Timezone: `Asia/Karachi` = UTC+5 fixed, no DST.

**RLS**: `is_member` pattern everywhere; members can select all household rows; members can insert/update `chores`, `chore_events`, `chore_assignments`, `purchases` (anyone can cover anyone, like v1 runs); `swap_requests` insert requires own `from_member_id`.

**Server tests**: extend `sql-test.mjs` + `api-test.mjs`: ensure_household (create/seed/reactivate/join), chore create/start-spawns-close/complete-parent-stamp, per-chore rotation + offset, swap cover+payback on a non-motor chore, purchases CRUD, RLS isolation. Add device-pool tables to `reset.mjs` (known gap).

## Phase 2 — Native alarms: keyed `syncAlarms`

Replace the two-slot API in `packages/motor-alarms` (Kotlin) + `app/src/alarm/native.ts`:

```ts
type AlarmSpec = { id: string; atMs: number; title: string; body: string };
syncAlarms(alarms: AlarmSpec[]): Promise<void>;   // full desired-state reconcile
snoozeAlarm(id: string, minutes: number): Promise<void>;
setSnoozeMinutes(n: number): Promise<void>;        // unchanged
// all permission/MIUI/battery/exact-alarm surfaces unchanged
```

Kotlin: persist the desired set as one JSON blob in SharedPreferences; PendingIntent action `"ghar.alarm.<id>"`, request code `id.hashCode()`; notification id derived from the id hash; intents carry `id/title/body` extras; `FullScreenAlarmActivity` renders generic title/body (accent styling) instead of the hardcoded motor copy; snooze action carries the id; **boot receiver iterates the blob** (arm future, drop past); on fire, re-arm the same id at +24h (daily rechain so strict recurring chores survive unopened apps — JS corrects the exact schedule on next open); switch to `setAlarmClock()` with `setExactAndAllowWhileIdle` fallback; single shared alarm channel (keep the delete-and-recreate trick + insistent loop). Delete `scheduleDaily`/`armStopAlarm`/`cancelStopAlarm`/`cancelDaily`/`snoozeStopAlarm` — one path only.

## Phase 3 — App logic + state (snappy built in)

- `app/src/logic/rotation.ts`: keep `localDate`/`addDays`/`dayNumber`/`activeMembersSorted`; replace `effectiveAssign` with `occursOn(chore, date)` (interval + monthly-day) and `assigneeFor(chore, date, members, overrides)` (override → rotate-offset → fixed assignee).
- `app/src/logic/alarms.ts`: `computeDesiredAlarms(me, chores, events, overrides, now): AlarmSpec[]` — my strict deadlines only: one-off `due_at`, recurring next occurrence (date + `time_of_day` at UTC+5), skip done/skipped/past->1h, include tomorrow's recurring (arm-ahead), cap nearest 8. Keep `formatRemaining`.
- `app/src/logic/ledger.ts`: monthly grouping + PKR formatting (ported from home-invoice).
- `app/src/db/api.ts`: fetch window = all active chores + events/overrides/swaps (±35d) + purchases (lazy, per-month query on Ledger screen); action wrappers for the new RPCs; delete old run/swap/onboarding calls.
- `app/src/db/client.ts`: `ensureDeviceSession` unchanged; add silent `ensureHousehold(name)` call path.
- **AppContext rewrite**: snapshot cache (`ghar.snapshot` in AsyncStorage — household, members, chores, events, overrides, swaps, savedAt) → boot renders the snapshot instantly while session+fetch settle (stale-while-revalidate; never block on network); optimistic actions (complete/start/skip/swap/purchase: apply locally, write in background, on error roll back + Alert + refresh); realtime channel gets the second `.on` for `households` by `id` (fixes settings propagation); alarm reconciler diffs `JSON.stringify(desired)` then calls `syncAlarms`.
- Onboarding = one name field (no picker — RLS hides members pre-join; duplicates are fine for a family).

## Phase 4 — Screens + navigation

Tabs: **Today · Chores · Ledger · Family** (bottom tabs, dark theme, existing `Screen`/`ui.tsx` components reused as-is).

- **NameScreen** (replaces Onboarding): "Ghar" logo, one line — your name → `ensure_household` → in.
- **TodayScreen**: hero ("N things on you today" / "All clear"); my-today cards (title, deadline time or soft, amount pill for bills, Done); motor-turn card when the rotating chore is mine and unstarted (Start); running card with live countdown + Close (completes the spawned chore); "Around the house" read-only list of others' today; pending swaps; **+ Add chore** → ChoreModal (title, note, assignee member-or-Rotating, schedule: Once date+time / Every N days / Monthly day N, "Ring an alarm" strict toggle, optional Rs amount, optional duration-minutes). ChoreModal doubles as edit; archive = `active=false`.
- **ChoresScreen**: Active chores (edit/archive) + Activity feed (last 14 days of events: who did what, missed, covered).
- **FamilyScreen**: members, snooze minutes, the whole "Make alarms reliable" checklist (unchanged — it's the crown jewel), test alarm (one-shot keyed alarm +1 min), leave.
- Delete: old OnboardingScreen, HistoryScreen grid, all motor copy ("YOUR TURN" hero becomes the chore card).

## Order & risk notes

- Phases are review checkpoints inside one v2.0.0 branch, not separate releases (the app compiles again from Phase 3 onward).
- Destructive migration wipes unused v1 data; DB rebuilt via `reset.mjs` + `migrate.mjs`.
- Old alarm channel/notification IDs are replaced — first v2 open re-syncs everything; existing MIUI permissions survive the package-id-unchanged update.
- Pool of 12 device accounts remains the invisible auth; `ensure_household` fixes the latent can't-rejoin-after-leave gap.
